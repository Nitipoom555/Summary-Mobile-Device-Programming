1. Android UI & Layout Structure

โครงสร้างของ Android Application

  • src: โฟลเดอร์เก็บโค้ด Java (Activity, Services, BroadcastReceivers, ContentProviders)
  • res: เก็บ Resources ได้แก่ drawable (รูป/ไอคอน), layout (ไฟล์ XML หน้าจอ), values (strings.xml, styles.xml), mipmap (ไอคอนแอปลงเครื่องตามขนาดจอ)
  • AndroidManifest.xml: ไฟล์แจ้งข้อมูลสำคัญของแอปให้ Android OS ทราบ (เช่น ประกาศ Activity, Permissions ต่างๆ, การเรียกใช้ Library)

Activity Life Cycles (วงจรชีวิต 6 สถานะหลัก)

ทุกๆ หน้าจอของ Android คือ 1 Activity และมี Lifecycle ของตัวเอง
  • onCreate(): ทำงานครั้งแรกและครั้งเดียวเมื่อ Activity ถูกสร้างขึ้น (มักใช้ตั้งค่าตัวแปรและ UI)
  • onStart(): Activity เข้าสู่สถานะ Started แอปเริ่มแสดงให้ผู้ใช้มองเห็นและโต้ตอบได้
  • onResume(): ถูกเรียกเมื่อผู้ใช้กลับเข้ามาที่ Activity นี้อีกครั้ง (หลังแอปไปอยู่เบื้องหลัง)
  • onPause(): สัญญาณแรกที่บอกว่าผู้ใช้กำลังจะออกจาก Activity นี้ (หน้าจอยังเห็นอยู่บางส่วน)
  • onStop(): Activity ไม่แสดงให้ผู้ใช้เห็นอีกต่อไป (Hidden)
  • onDestroy(): ถูกเรียกก่อนที่ Activity จะถูกทำลายทิ้ง คืนหน่วยความจำระบบ

ประเภทของ Layout (ViewGroup)

  • LinearLayout: จัดเรียงลูกแบบทางเดียว (เรียงแนวตั้ง Vertical หรือแนวนอน Horizontal)
  • RelativeLayout: อ้างอิงตำแหน่งกับวัตถุอื่น (Sibling) หรือขอบของหน้าจอ (Parent) เช่น layout_below, layout_toLeftOf
  • TableLayout: จัดกลุ่มแบบตาราง (Row/Column) ไม่มีเส้นขอบ ต้องใช้คู่กับ <TableRow>
  • AbsoluteLayout: กำหนดพิกัด X, Y แบบเจาะจง (ไม่แนะนำ เพราะจอมือถือมีหลายขนาด)
  • FrameLayout: ทำหน้าที่เป็น Placeholder ใช้แสดง View ชิ้นเดียวซ้อนทับกัน (Z-index)
  • ScrollView: ทำให้หน้าจอเลื่อนได้ สำคัญ: ภายใน ScrollView สามารถมีลูกได้แค่ 1 ตัวเท่านั้น (ส่วนมากจะยัด LinearLayout ไว้ข้างในสุด)
  • GridView / ListView: แสดงข้อมูลแบบตาราง 2 มิติ หรือแบบรายการเลื่อนแนวตั้ง

UI Elements & Attributes

  • หน่วยวัด: dp (ใช้กำหนดขนาดกว้าง/ยาว), sp (ใช้กับขนาด Font จะปรับตาม Setting เครื่อง), px, pt
  • ขนาด: wrap_content (ยืดตามเนื้อหาข้างใน), match_parent / fill_parent (ขยายเต็มพื้นที่ของแม่)
  • Views: TextView, Button, ImageView, EditText, CheckBox (เลือกได้หลายอัน), RadioButton (เลือกได้อันเดียวในกลุ่ม), Switch (เปิด/ปิด), ProgressBar (แถบดาวน์โหลด), SeekBar (แถบเลื่อนค่า เช่น ปรับเสียง)
  • Window Insets: การจัดการกับพื้นที่ระบบ (Status Bar, Navigation Bar) ใช้ ViewCompat.setOnApplyWindowInsetsListener เพื่อสร้าง Edge-to-edge design

2. Mobile User Interface Design (Chapter 3)

หลักจิตวิทยาและการทำความเข้าใจผู้ใช้

  • Proximity (ความใกล้ชิด): วัตถุที่วางอยู่ใกล้กัน ผู้ใช้จะตีความว่ามันคือกลุ่มเดียวกัน
  • Closure (การปิดทับ): สมองผู้ใช้สามารถเติมเต็มข้อมูลที่ขาดหายไปได้เอง (เช่น รูปทรงสามเหลี่ยมที่วาดไม่เสร็จ)
  • Figure and Ground: การแยกพื้นหน้า (Figure) และพื้นหลัง (Ground) ออกจากกันให้ชัดเจน ช่วยให้ผู้ใช้ทำงานรวดเร็วและไม่สับสน
  • Similarity: สัญลักษณ์ สี หรือขนาดที่เหมือนกัน ผู้ใช้จะจัดว่ามันทำงานคล้ายกัน
  • Social Aspect: แอพควรมีฟีเจอร์แชร์ข้อมูลให้สังคมออนไลน์ทราบ เช่น ปุ่ม Tweet/Share

Usability (ความง่ายในการใช้งาน)

  • Error Protection: ป้องกันผู้ใช้ทำผิดพลาด ต้องสามารถย้อนกลับ (Back) หรือยกเลิก (Undo) ได้ และควรมี Log file เก็บประวัติ
  • Actual vs Perceived Target: พื้นที่ที่ผู้ใช้มองเห็น (Perceived) ไม่จำเป็นต้องเท่ากับพื้นที่ที่กดได้ (Actual) ปุ่มเล็กๆ ควรเว้น Whitespace (Actual Target) ให้กดง่ายขึ้น
  • Gesture Design: ออกแบบการลากนิ้ว เช่น Tap, Flick, Pinch (บีบซูม), Spread, Drag

Accessibility (การเข้าถึงสำหรับทุกคน)

  • Hearing: คนหูหนวก ควรใช้สัญลักษณ์คู่กับเสียงเสมอ
  • Vision: คนตาบอด ควรใช้ระบบเสียงสั่งงาน (VoiceOver)
  • Speech & Dexterity: สั่งด้วยวาจา และออกแบบให้รองรับ Gesture หลายแบบ
  • Cognition: สำหรับเด็กและคนชรา ใช้เมนูชัดเจน (Clear Navigation)

Mobile Information Design Patterns

  • Navigation (นำทาง):
    • Annunciator Panel (แถบแสดงสถานะด้านบน)
    • Fixed Menu (เมนูตายตัว นิยมใช้สุด)
    • Expandable Menu (เมนูย่อ/ขยายได้ เช่น Hamburger menu)
    • Scroll (ควรเลื่อนได้แค่แกนเดียวเท่านั้น)
  • Intervening Screens (หน้าจอคั่น): Splash Screen (โหลดหน้าแรก), Loading Screen, Advertising (โฆษณา ไม่ควรทำให้น่ารำคาญ)
  • Content Structure: Hierarchy ความลึกไม่ควรเกิน 3 ระดับ, ใช้อ่านจากซ้ายไปขวา (Single-column layout), ไม่ควรใช้ Animation กับข้อความ

3. Intents and Services (Chapter 4)

Intents

Intent คือออบเจกต์ที่ใช้ส่งผ่านข้อมูลและควบคุมการสั่งงานระหว่าง Activity

  • องค์ประกอบหลักของ Intent:
    • Action: การกระทำ เช่น ACTION_VIEW, ACTION_EDIT, ACTION_CALL, ACTION_DIAL
    • Data: ข้อมูลที่ใช้ทำงานด้วย (มักอยู่ในรูปแบบ URI เช่น tel:555-1234 หรือ geo:0,0?q=...)
// ตัวอย่างการใช้ ACTION_DIAL
String myData = "tel:555-1234";
Intent myActivity = new Intent(Intent.ACTION_DIAL, Uri.parse(myData));
startActivity(myActivity);

การรับผลลัพธ์กลับมาจาก Activity

  • เรียกหน้าถัดไปด้วย: startActivityForResult(intent, requestCodeID)
  • หน้าลูกที่ถูกเรียก (Child) ส่งผลลัพธ์กลับด้วย: setResult(resultCode) (เช่น Activity.RESULT_OK)
  • หน้าแม่ (Parent) รอรับผลลัพธ์ผ่านเมธอด: onActivityResult(requestCodeID, resultCode, Intent data)

Services (กระบวนการเบื้องหลัง)

คอมโพเนนต์ที่ไม่มีหน้าตา (No UI) ทำงานอยู่ Background Thread

  • Started Service:
    • เรียกโดย startService()
    • มักทำงานแบบ Single Operation (ทำงานเดียว) เมื่อเสร็จงาน Service สามารถหยุดตัวเองได้ (Stopped)
    • ไม่ส่งผลลัพธ์กลับให้คนเรียกโดยตรง
  • Bound Service:
    • เรียกโดย bindService()
    • ทำงานแบบ Client-Server Interface ยอมให้ Component ภายนอกมาเชื่อมต่อ แลกเปลี่ยนข้อมูลและส่ง Request หากันได้ (ผ่าน IPC)
    • Service จะทำงานตราบเท่าที่มีคน Bind ไว้ (Unbound ก็คือหยุด)

4. SQLite Database (Chapter 5)

คุณสมบัติของ SQLite

  • ระบบฐานข้อมูลเชิงสัมพันธ์แบบ Transactional ฝังมาใน Android
  • ขนาดเล็กมาก (น้อยกว่า 400KB), เป็น Zero-configuration, และ Open Source
  • สำคัญ: ไม่มีนามสกุลไฟล์ ไม่ต้องการ Server ทำงานแบบ Local ล้วนๆ
  • Case Insensitive: ไม่สนใจตัวพิมพ์เล็ก/ใหญ่ (Piyanart กับ PIYANART คือตัวเดียวกัน)
  • ไม่มี Data type checking: สามารถเอา String ไปใส่ในคอลัมน์ Integer ได้ (กำหนดชนิดเป็นราย Value ไม่ใช่ราย Column เหมือน DB ปกติ)

ตำแหน่งการเก็บฐานข้อมูล

  • Internal Memory: /data/data/<package_name>/ (เป็นความลับ แอปอื่นเข้าถึงไม่ได้)
  • SD Card (External): ต้องขอ Permission WRITE_EXTERNAL_STORAGE และ READ_EXTERNAL_STORAGE ข้อมูลจะเป็น Public

คำสั่งในการจัดการและเข้าถึง

// การเปิดหรือสร้างฐานข้อมูล
SQLiteDatabase db = this.openOrCreateDatabase("myfriendsDB", MODE_PRIVATE, null);

// Action Queries (Insert, Update, Delete) สามารถใช้ execSQL() ได้ แต่แนะนำให้ใช้ Method โดยตรง
ContentValues values = new ContentValues();
values.put("name", "ABC");
db.insert("table_name", null, values);

// การใช้งาน Transaction
db.beginTransaction();
try {
    // operations...
    db.setTransactionSuccessful(); // ถ้าไม่เรียกบรรทัดนี้ จะทำการ Rollback ทันที
} finally {
    db.endTransaction();
}

Cursor (ตัววนอ่านข้อมูล)

  • ใช้ในการทำ Retrieval Query (SELECT) ผลลัพธ์ที่ได้จะอยู่ใน Cursor
  • ใน Android Cursor จะทำงานแบบ Read-only (อ่านได้อย่างเดียว) และ One row-at-the-time (อ่านทีละบรรทัด)
  • เมธอดสำคัญ: rawQuery(), moveToFirst(), moveToNext(), getInt(), getString()

5. Communication via Network and Web (Chapter 6)

WebView Features

  • ใช้ Engine WebKit Open Source
  • ไม่ใช่ Browser แบบเต็มรูปแบบ (ไม่มีปุ่ม Back/Forward, ช่องกรอก URL มาให้ ต้องทำเอง)
  • สิ่งจำเป็นสุด: ต้องเพิ่ม Permission ใน Manifest 👉 <uses-permission android:name="android.permission.INTERNET"/>
  • คำสั่งพื้นฐาน: loadUrl(), goBack(), goForward(), reload(), clearCache()

Design Strategies (กลยุทธ์การพัฒนา)

  • Pure Android: เขียนด้วย Native Android SDK ได้ UI ตอบสนองเร็ว แต่ข้อเสียคือพอร์ตไป iOS ไม่ได้ ต้องเขียนใหม่หมด
  • Pure External HTML: ทำเป็นเว็บวางบนเซิร์ฟเวอร์ พกพาง่ายสุด (Portable) แต่เข้าถึง Hardware มือถือไม่ได้
  • Mixed Mode (HTML + Android): เอากระบวนการทั้งสองมารวมกัน นำไฟล์ HTML มาไว้ในเครื่อง และใช้ JavaScript Interface เพื่อเป็นสะพานเชื่อมให้หน้าเว็บสามารถเรียกใช้เซนเซอร์หรือ Hardware ของแอนดรอยด์ได้

6. Notification & Alarms (Android Notify & Ch.8)

Notification Process

  • แสดงผลบน Status Bar และเมื่อลากลงมาจะอยู่ใน Notification Drawer
  • บริหารจัดการโดยระบบของ OS ที่ชื่อว่า Notification Manager
  • Notification Channel: (บังคับใช้ใน Android 8.0+) คือ "กล่อง" จัดกลุ่มการแจ้งเตือน ผู้ใช้สามารถตั้งค่าความสำคัญ (Importance) ของกลุ่มนี้ได้เอง เช่น ตั้งเป็น IMPORTANCE_HIGH (เด้งเตือนแบบ Heads-up), DEFAULT (สั่น/มีเสียง), LOW (ไม่มีเสียงโชว์แค่ไอคอน) หรือ MIN
    * Channel ID สร้างแล้วห้ามซ้ำ และถ้าเคยสร้างไว้แล้วไม่สามารถสร้างใหม่ทับได้ ระบบจะพัง
  • NotificationCompat.Builder: คลาสหลักในการสร้าง แจ้งเตือน ประกอบด้วย
    • setSmallIcon(): ห้ามลืมเด็ดขาด ถ้าลืมแอปจะ Crash
    • setContentTitle(), setContentText()
    • setStyle(): ทำรูปแบพิเศษ เช่น BigTextStyle, InboxStyle, MessagingStyle
    • setContentIntent(): กำหนด PendingIntent สำหรับสั่งให้ทำงานเมื่อผู้ใช้กดจิ้มที่แจ้งเตือน (เช่น สั่งเปิดหน้า Activity ใหม่)

Alarms (ตั้งเวลา)

  • บริหารจัดการด้วย AlarmManager โดยมักตั้งค่าเวลา (เช่น RTC_WAKEUP คืออิงเวลาโลกและปลุกจอขึ้นมาทำงาน)
  • ทำงานคู่กับ PendingIntent.getBroadcast() เพื่อยิงสัญญาณไปปลุก BroadcastReceiver
  • มีคลาส WakefulBroadcastReceiver (สมัยก่อน) หรือใช้ JobScheduler/WorkManager ในปัจจุบันเพื่อควบคุมการตื่นของ CPU ให้ประหยัดแบตเตอรี่

7. Graphic & Animation (Chapter 9)

Canvas (การวาด 2D)

  • เครื่องมือวาด 2D ระดับล่าง (Low level) ลงบนหน้าจอโดยตรง วาดได้ 2 ทางคือ วาดลง View Object (พบบ่อย) และวาดลง Canvas โดยตรง (ใช้ในเกม)
  • วิธีการวาดต้อง Override เมธอด onDraw(Canvas canvas) ของ View
  • เมธอดสำคัญ: drawText(), drawRoundRect(), drawCircle(), drawBitmap() โดยกำหนดสีและสไตล์ผ่านออบเจกต์ Paint

ระบบ 3 Animations ของ Android

  1. Property Animation: แนะนำให้ใช้มากที่สุด เปลี่ยนแปลงคุณสมบัติ (Property) ของวัตถุจริงๆ ถ้าขยับปุ่มจากจุด A ไป B จะสามารถกดปุ่มที่จุด B ได้
  2. View Animation: ใช้เฉพาะกับคลาส View หมุน/ย่อ/ขยาย ขยับเฉพาะตัวภาพ แต่ตำแหน่งจับการคลิก ยังอยู่ที่เดิม เปลี่ยนสีพื้นหลังไม่ได้ด้วยวิธีนี้
  3. Drawable Animation: ทำแอนิเมชันแบบ Flip book (ฟิล์มภาพยนตร์) โชว์ภาพเรียงกันแบบเฟรมต่อเฟรม (Frame by frame) กำหนดผ่าน XML <animation-list>

Physics-based animation: แอนิเมชันเชิงฟิสิกส์ เช่น Spring (ตั้งค่าความแข็ง/ความหน่วง), Fling (แรงต้าน แรงเสียดทานค่อยๆหยุด)

OpenGL ES

  • API มาตรฐานสำหรับกราฟิก 3D (รองรับตั้งแต่ ES 1.0 ไปจนถึง 3.1)
  • ใช้คลาส GLSurfaceView ในการวาด และ GLSurfaceView.Renderer เป็น Interface ควบคุม
  • ฟังก์ชันสำคัญใน Renderer: onSurfaceCreated() (เรียกครั้งเดียวตอนเริ่ม), onDrawFrame() (เรียกเมื่อต้องวาดเฟรมใหม่ซ้ำๆ), onSurfaceChanged() (เรียกเมื่อหมุนจอพลิกไปมา)

8. Multimedia (Chapter 10)

คลาส MediaPlayer

  • คลาสที่ Android มีให้สำหรับถอดรหัส (Decode) และเล่นไฟล์ เสียง (Audio) และ วิดีโอ (Video) ได้อย่างง่ายดาย
  • แหล่งที่มาของไฟล์ (Data Source): โฟลเดอร์ในแอป res/raw, ไฟล์ใน SD Card, สตรีมทางไกล (URL Network Connection)
  • เมธอดสำคัญ: setDataSource(), prepare() (สำคัญ: ต้องรอให้เตรียมไฟล์เสร็จก่อน), start(), pause(), stop(), release() (คืนหน่วยความจำ)

รูปแบบไฟล์ที่รองรับ (Format Supported)

  • Video Codec: H.263, H.264 AVC (ใช้กับ .mp4, .3gp), MPEG-4 SP, VP8 (ใช้กับ .webm หรือ .mkv)
  • Audio: AAC-LC

9. Location Service (LBS) (Chapter 11)

หลักการหาพิกัด (Positioning)

  • GPS (Global Positioning System): ใช้ดาวเทียมโคจรรอบโลก 27 ดวง (ทำงาน 24 สำรอง 3) อาศัยการตัดกันของวงกลมพิกัด (2-D Trilateration) อย่างน้อย 3-4 ดวง ให้ความแม่นยำสูงสุด (Accuracy)
  • Cell Tower Triangulation: คำนวณความเร็ว (Lag time/Ping) ระหว่างมือถือไปยังเสาสัญญาณเครือข่ายมือถือ 3 ต้นที่อยู่ใกล้สุด

โครงสร้างคลาสของ Location

  • LocationManager: ร้องขอบริการระบบพิกัดจากตัว OS
  • LocationListener: Interface สำหรับรอรับเหตุการณ์ (Event) เช่น
    • onLocationChanged(): เมื่อตำแหน่งเปลี่ยน
    • onProviderDisabled() / onProviderEnabled(): เมื่อผู้ใช้ปิด/เปิด GPS
  • Location: ออบเจกต์เก็บพิกัด Latitude, Longitude, Altitude (ความสูง), Speed, Bearing
  • การใช้งานจริง ต้องเรียกผ่าน requestLocationUpdates(Provider, minTime, minDistance, LocationListener)
Google Maps API:
1. ต้องสร้างและใช้ API Key จาก Google Cloud
2. ต้องเพิ่ม Permission ACCESS_COARSE_LOCATION (หรือ FINE) และ INTERNET ใน Manifest

10. Mobile Security and Hacking (Chapter 12)

สาเหตุที่ต้องรักษาความปลอดภัย (Sensitive Data)

  • โทรศัพท์เก็บข้อมูลส่วนตัวมากมาย เช่น รหัสผ่าน ข้อมูลบัตรเครดิต ประวัติสุขภาพ รูปภาพ ทัศนคติทางการเมือง (จัดเป็นข้อมูลอ่อนไหว)
  • เป้าหมายหลักของการโจมตี 3 อย่าง:
    1. Data (ขโมยข้อมูล)
    2. Identity (ขโมยตัวตนผู้ใช้ สวมรอย)
    3. Availability (โจมตีเพื่อระงับการใช้งานเครื่อง เช่น ทำให้รีสตาร์ทวนลูป)

ความเสี่ยง และ ช่องโหว่ต่างๆ (Risks & Vulnerabilities)

  • ด้าน Network: การใช้ HTTP ธรรมดา แทนที่จะใช้ HTTPS (ไม่เข้ารหัสข้อมูล), การส่งข้อมูลผ่าน Wi-Fi สาธารณะ (ดักจับข้อมูล Eavesdropping ป้องกันด้วยโปรโตคอล WPA/TKIP)
  • ด้าน SMS/MMS: ส่ง Binary block พิเศษทำให้เครื่องแครช/รีสตาร์ท หรือส่ง MMS แนบไวรัส (Malware) ไปติดเครื่องอื่น
  • ด้าน Hardware:
    • Juice Jacking: การโจมตีผ่านช่องเสียบ USB ชาร์จไฟสาธารณะ เพื่อแอบดูดข้อมูล (Data exfiltration) หรือติดตั้งมัลแวร์
    • Rooting / Jail-breaking: ผู้ใช้ไปปลดล็อกสิทธิ์ OS ขั้นสูงสุด ทำให้ระบบรักษาความปลอดภัยดั้งเดิม (Sandbox) ของ OS ถูกทำลาย
  • GSM Networks: การทำเสาสัญญาณปลอม (Fake base station) ขโมยข้อมูลมือถือ

มาตรฐานและการป้องกัน

  • OWASP (Open Web Application Security Project): องค์กรหลักที่ออกมาตรฐานการรักษาความปลอดภัย
  • CVSS: ระบบการให้คะแนนช่องโหว่ความปลอดภัย
  • คำแนะนำ: ใช้ OAuth2 ในการล็อกอิน, อย่าเก็บ Password ไว้ตรงๆ (ต้อง Encrypt), เคลียร์ Memory เมื่อไม่ใช้, หลีกเลี่ยงการบันทึก Sensitive data นอกระบบที่ปลอดภัยของแอป
